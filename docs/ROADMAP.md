# 로드맵 — 버전별 상세 계획

> **살아 있는 계획은 이 문서 하나.** 끝난 버전은 이 문서에서 지우고 `CHANGELOG.md`(받는 사람용)와
> git log(왜)로 넘긴다. 순서·범위를 바꾸면 그 자리에서 고친다(새 블록을 위에 얹지 않는다).
> 2026-10-04 사용자와 합의한 결정이 전부 반영돼 있다. 구현은 버전 단위로 "진행시켜" 받은 뒤 시작한다.

## 버전 규칙

`a.b.c` — **a** 큰 패치(구조가 바뀌어 새로 익혀야 함: 메뉴 재편 · 저장 형식 큰 변경) · **b** 중간(새 기능·화면) ·
**c** 작은 수정(버그·문구·작은 성능). 섞이면 큰 쪽을 올리고 **아래 자리는 1로** 돌린다(1.4.2 → 2.1.1).
예외: 공개판 1.0.2 의 가운데가 0 이라 창 크기 수정만 1.0.3, 다음 기능 패치(1.1.1)부터 새 규칙.
`updatecheck` 는 세 자리 숫자 비교라 이 체계에서 그대로 동작한다.

## 모든 버전 공통 — 끝났다고 보는 기준

1. 새 코드마다 테스트 + **일부러 되돌린 변이가 FAIL** 하는지(`mutate.js` 또는 손 변이). 커밋 메시지에 "변이 N건 FAIL".
2. 테스트 6종 통과 · CI 초록 · `check_api.py` 에 새 출처마다 한 줄.
3. 1만 경기 계정으로 **검색→첫 화면 · 메뉴 전환 시간**을 이전 값과 비교(지금: 마지막 계정 약 1.3초, 메뉴 0.3초 이하).
4. 창 1280×720(1.0.3 뒤로는 작은 화면 최소 높이 포함)에서 잘림 없음 — 기존 offscreen 테스트.
5. exe 빌드 → 2번 모니터 스모크(창을 띄워야 할 때) · 크래시 로그 증가 0.
6. `CHANGELOG.md` 절 · README · 프로젝트 `CLAUDE.md` 파일 표 갱신 → `release.py` → 공개 명령은 사용자.
7. 홈페이지(데이터센터)를 새로 읽는 기능은 전부 `config.WEB_DATA` 뒤 + `test_web_data_switch_blocks_every_request` 에 등록.
   이용 안내 문구가 실질적으로 바뀌면 `NOTICE_VERSION` 을 올린다.

## 1.0.3 — 창 크기 (가장 먼저)

**문제(실측)** 기본 1600×900 이 작은 화면보다 크다. 그리고 최소 1280×720 도 제목줄(약 31)·작업 표시줄을 빼면
1366×768(쓸 수 있는 높이 약 728) · FHD 150% 배율(논리 1280×720, 높이 약 680)에 안 들어간다.
`MIN_WINDOW` 주석의 "1366x768 노트북에도 들어간다"는 틀렸다.

**규칙** 판정은 모니터 해상도가 아니라 **배율을 반영한 쓸 수 있는 크기**(`QScreen.availableGeometry`).
- 쓸 수 있는 크기 ≥ 1600×900 + 테두리 → 1600×900
- ≥ 1280×720 + 테두리 → 1280×720
- 그것도 안 되면 → **최대화로 열기** + 최소 높이를 `MIN_HEIGHT_SMALL` 로 낮춤(폭 1280 유지 — 표 기준)

**설계**
- `app_main.py` 상단: `DEFAULT_WINDOW = (1600, 900)` · `MIN_WINDOW` 주석 정정 · `MIN_HEIGHT_SMALL`(값은 아래 측정으로).
- `initial_window(avail: QRect, frame: QMargins) -> tuple[str, QSize | None]` — `("normal", 크기)` 또는 `("maximized", None)`.
  순수 함수라 화면 없이 테스트한다.
- `MainWindow.__init__` · `_load_settings`: 저장된 크기가 있으면 복원하되 **지금 화면보다 크면 줄인다**. 없으면 위 규칙.
  `main()`: `"maximized"` 면 `showMaximized()`. 박혀 있던 `resize(1600, 900)` 두 곳을 상수로.
- `MIN_HEIGHT_SMALL` 정하기: 기존 "최소 크기에서 잘림 없음" 테스트를 높이만 낮춰 돌려, 세로 스크롤만 생기고 가로 잘림이
  없는 가장 작은 높이(예상 620~650). 페이지가 `VScrollArea` 라 세로는 스크롤로 해결된다.

**테스트** `initial_window` 4경우(FHD 100% · FHD 125% · FHD 150% · 1366×768) + 경계 1픽셀 · 저장 크기 줄이기 ·
낮춘 최소 높이에서 잘림 없음. 변이: 경계 비교 뒤집기 · 최대화 분기 빼기.
**실화면 확인** 2번 모니터(1920×1080)에서 `QT_SCALE_FACTOR=1.5` 로 exe 실행 → Qt 가 1280×720 화면으로 본다 → 최대화로 열리는지.
**규모** 작음.

  spid, grade, value)` — 이미 있는 거래(sale_sn)를 만나면 멈추는 이어 받기. **얼마나 과거까지 나오는지 먼저 실측.**
  **검색한 계정 본인 화면에만** 쓴다(남의 지출을 들여다보는 기능은 만들지 않는다).
- **B 카드 캐시(시세만)** — 평가 손익에 지금 시세가 필요하다. `PlayerInfo.prices`(강화 단계별 시세)를
  `store.card_prices(spid, grade, price, fetched_at)` 에 하루 캐시. 2.1.1 에서 급여·OVR 로 넓힌다.
- **스쿼드 타임라인(1 + N4 합침)** — `squad_timeline.py`: 거래(구매·판매일) + 경기 스쿼드(처음·마지막 출전, 강화 변화)
  → `TimelineEvent` 목록 · 사건마다 전후 승률·득실. 보유 중이면 "진행 중", 사 놓고 안 쓰면 "미출전", 거래가 없는
  변경은 "추정". 원인이라고 단정하지 않는 문구.
- **N3 이적시장 가계부** — 총 지출·수입·순지출 · 판 선수 **실현 손익** · 보유 선수 **평가 손익**(오늘 시세) · 팩·보상은
  "취득가 없음". 짝 맞추기는 같은 카드끼리 선입선출, 강화 변화 표시. 화면에 "이적시장 기준(강화 비용 제외)".
  판매 금액이 수수료를 뗀 값인지 실제 거래로 대조.
- **새 메뉴 "스쿼드·이적"** — 타임라인 / 가계부 두 화면(1.x 라 페이지 안 탭 대신 메뉴 두 줄, 2.1.1 에서 탭으로).
- **N1 내 선수 vs 랭커 평균** — `nexon_api.get_ranker_stats(matchtype, [(spid, po)])`(감독모드 52) → 같은 카드·포지션
  경기당 기록 비교(%). 하루 캐시, 집계 기준일(`createDate`) 표시. 문구는 "조작 실력"이 아니라 **전술 효과**.
- **N2 영입 스카우팅** — 선수 카드 창에 "랭커 기록" 탭(아직 안 쓰는 카드도).
- **N5 패스 스타일** — `stats.pass_style(details, ouid)`: 패스 종류별 비중·성공률, 이긴/진 경기 비교 → 전술 화면 구역.
- **N6 어시스트 위치 맵** — `ShotMapWidget` 에 어시스트 표시(`assistX/Y`) → 슛 맵에 전환.
- **N9 선수별 평점 추이** — 카드마다 주 단위 평점 → 선수 카드 "내 기록" 탭.

**규모** 큼.

## 2.1.1 — 메뉴 재편 + 스쿼드·랭커 (큰 패치)

- **페이지 안 탭** — `widgets.PageTabs`(데이터센터 데일리차트처럼 칸이 나뉜 탭줄, 색은 우리 테마). 고른 탭만 그린다
  (`PAGE_RENDER_KEYS` 를 (메뉴, 탭) 단위로). 보던 탭 기억(`view/tab/<메뉴>`).
  - 선수 지표[지표 · 랭커 비교] · 전술·경기 결과[전술 · 경기 결과 · 패스 스타일] · 성적 진단[상대·점유율 · 규율·불운]
    · 슛 맵[슛 · 어시스트] · 승률 그래프[승률·등급 · 점수·예측] · 스쿼드·이적[타임라인 · 가계부] · 랭커 픽[픽 · 추천]
  - 새 메뉴 묶음 "랭커": 랭킹 추이 · 랭커 픽 · 선수로 구단주 찾기. 메뉴는 약 21개(지금 18).
- **B 카드 캐시 전체** — `store.card_info(spid, grade, price, salary, ovr, fetched_at)`. 출처 둘(선수 페이지 · 팀컬러 선수
  JSON)을 한 저장소로.
- **C 스쿼드 축구장 위젯 v2** — 포지션 줄별 배치로 **겹치지 않게**(GK · 수비 · 수비형 · 중앙 · 공격형 · 공격), 칩에
  포지션 · OVR · 강화 · 시세 · 이름, 위에 스쿼드 가치 · 급여. 홈페이지 데이터가 꺼지면 시세·급여 칸만 비움.
- **⑨ 포지션별 최다 상대** → 축구장 배치 + 옆에 팀컬러 검색·선택. 앱의 다른 스쿼드 화면도 v2 로 통일.
- **① 구단주 비교** — 지표 표 자세히 · 키플레이어(골·평점 상위) 비교 · 접었다 펴는 지표 카드 · 양쪽 v2 스쿼드.
- **6 랭커 픽(상위 200)** — 스냅숏 1~200위 → 닉네임→ouid(캐시) → 최근 경기 선발 → 팀컬러·포메이션·선발 카드·
  강화 분포 + 내 스쿼드 vs 랭커. 수집은 A 의 일정에 붙인다(토글 하나).
- **12 선수로 구단주 찾기** — `store.match_squads(match_id, ouid, sp_id, grade, position)` 색인 + 기존 경기 백필(한 번,
  뒤에서). 조건: 팀컬러 + 카드 시즌(`stats.season_id_of`) + 선수 → 그 카드를 **지금**(그 유저 최근 경기, 기본 30일) 쓰는 유저.
  범위: 내 DB 구단주 + 상위 200.
- **P2 랭킹 추이 그래프** — 포메이션 비율 · 순위 구간별 ELO(상위 구간 200위) · 구단가치 평균·중앙값 · 팀컬러 픽률.
- **11-lite 랭커 기반 추천·평가** — 팀컬러별 상위 N명(초안 30, 분포를 보고 확정, 10명 미만이면 추천 안 함, 순위 범위 표시)
  → 포지션별 대체 선수 · 내 스쿼드 위치(구단가치·강화·포메이션).

**규모** 가장 큼 — 메뉴를 한 번에 바꾸므로 1.x 기능을 제자리 탭으로 옮기는 회귀 확인이 핵심.
