## 버전 규칙

`a.b.c` — **a** 큰 패치(구조가 바뀌어 새로 익혀야 함: 메뉴 재편 · 저장 형식 큰 변경) · **b** 중간(새 기능·화면) ·
**c** 작은 수정(버그·문구·작은 성능). 섞이면 큰 쪽을 올리고 **아래 자리는 1로** 돌린다(1.4.2 → 2.1.1).
예외: 공개판 1.0.2 의 가운데가 0 이라 창 크기 수정만 1.0.3, 다음 기능 패치(1.1.1)부터 새 규칙.
`updatecheck` 는 세 자리 숫자 비교라 이 체계에서 그대로 동작한다.

- `min_sigma`(지표) = `G ÷ 1.28`. G 는 칩이 의미 있으려면 필요한 최소 크기 — 칩 조건 "축소 백분위 ≤ 10 또는 ≥ 90" 이 `|d* − m| ≥ 1.28σ` 라서 σ 가 G/1.28 보다 작으면 의미 있는 크기의 칩이 아예 못 뜬다. **G**: 비율 지표(결정력·유효슛 비율·유효슛당 골·태클 성공)는 `N19_MIN_GAP`(2.5%p) · 롱·스루 비율은 41단계 A1 문턱 2.8%p · 점유율 5%p · 경기당 슛 0.4 · 경기당 태클 0.9 (모두 DONE.md 41단계 A1 의 "상대 값 10% 문턱") · **경기당 유효슛은 41단계에 값이 없어 같은 규칙(층 가중 구단주 상대 쪽 평균의 10%)을 실측에서 계산**.

- **판정 (U2 · 4판 — 덜어 냄, 3회차 [상]1 · [중])**: 지표마다 구단주 diff 에서 **층 크기 가중**(`w = 층 인구 ÷ 층 표본`)으로 가중 중앙값 m · 가중 분산 v · 가중 평균 se² s2, 참 sd `σ = √max(v − s2, 0)`, **유효 표본 `n_eff = (Σw)²/Σw²`**(Kish — 가중 2:8:20:70 이면 300명이 약 140) · `se_m = 1.253·√v / √n_eff`(4판 — 3판의 `√n` 은 가중을 무시해 약 1.46배 작았다). 이 값들은 바퀴 완료 때 작업 스레드가 `owner_dist_stats` 에 한 번 계산해 두고 **화면은 읽기 + 닫힌 식(지표 9개, 1ms 미만)** 만 한다 — 부트스트랩·경험 CDF·모의실험은 단계 0 스크래치에서만 쓴다.
  **판정 대상 지표**: `σ ≥ OWNER_DIST_METRIC_RULES[지표].min_sigma` AND `σ²/v ≥ .min_ratio` AND 단계 0 ⑤ 의 정규 근사 검사를 통과. 아니면 그 지표만 41단계 판정(`Diff.clear(N19_MIN_GAP)` · 창출 5% · **6판 — 5회차 [중]4: 창 통일을 철회한다** — 분포 모드 칩만 `OWNER_DIST_MY_DAYS` 창 값으로 계산하고 분모 하한 `N19_MIN_SHOTS`/`N19_MIN_TACKLES` 도 그 창 값에 건다 — **창 값이 하한 밑이면 그 지표만 41단계 판정(화면 범위)으로 돌린다**(7판 — 6회차 경계: 5판의 "미달이면 칩 없음" 대체, 철회 근거 "예전에 뜨던 칩이 사라진다" 가 분포 대상 지표에도 걸린다). **41단계 판정으로 남은 지표는 원래 화면 범위(시즌 등)를 그대로 쓴다**(하위 호환 — 안 그러면 경기가 적은 창에서 예전에 뜨던 칩이 사라진다). 두 기준이 달라도 줄이 기준 그룹으로 나뉘고 툴팁이 "기준·기간"을 적어 섞여 읽히지 않는다). **층 안 백분위는 내지 않는다**(4판 — 층당 75명 이하라 안정성 기준을 거치지 않고 판정되는 길이 생기고, 보여 줄 가치보다 구멍이 컸다).
  **내 값의 오차**: 내 diff `d` 와 se `se_me` 로 m 쪽으로 줄인다 `d* = m + (d − m)·σ²/(σ² + se_me²)`, 백분위 = Φ((d* − m) ÷ σ).
  **칩은 판정 기준 하나**: 분포 모드(판정 대상 지표)에서는 `Diff.clear`(같은 경기 상대 0 대비)를 쓰지 않는다 — 0 과 m 은 다른 기준이라 상위 구단주는 m > 0 이어서 약점 칩이 계통적으로 막힌다. 칩 = **축소 백분위 ≤ 10 또는 ≥ 90** AND `|d − m| ≥ 2·√(se_me² + se_m²)`. 툴팁에 **어느 기준인지**("분포 N명 대비" / "같은 경기 상대 대비")를 적는다. **넣지 않는 것**: 수수료 계산기 · 스쿼드 메이커(추천 스쿼드 자동) — "하지 않기로 한 것" · 다른 구단주 보상 랭킹 · 랭킹 밖 수집 ·
모든 구단주 경기를 받아야 하는 표(사용자 한 명의 API 키 한도 밖).

## 버전 미정 후보

### 승격 회차 A7 · N22 (2026-10-12 43단계에서 뺐다 — 사용자 결정 (a))

내 경기 `division`(감독모드 52 · `matches.payload` 의 `matchInfo[].division`)에서 10경기 회차를 되짚어 승급선 표(A7)와 "N승 남음"(N22)을 내려던 것. 실측(스크래치 스크립트 3개 — 저장소 밖, 읽기 전용) 결과 **규칙표를 데이터에서 거꾸로 세울 근거가 모자라** 뺐다.
- 등급 변화가 10경기 위상에 안 몰린다: 계정 6개에서 `경기 인덱스 mod 10` 최다 위상 14~26%(무작위 10%) · 변화 사이 간격은 7~10 에 몰림 → **조기 확정**이 있다(승격은 4경기째 12점에도, 강등은 7~10경기째). 등급이 안 바뀐 회차는 DB 에 안 보인다.
- 승점 3·1·0 으로 센 승격 승점: division 1100·1200·1300 은 최소 12 — 단 **들어온 방향에 따라 갈린다**. 강등돼 내려온 뒤(위에서)는 12점부터 승격, 승격해 올라온 뒤(아래서)는 대부분 14~17점. 10경기를 채우고 12·13점으로 강등된 게 division 1100 에서 10번(연속 10경기 · 직전 경기 간격 0.2시간 — 기록 빠짐 아님). division 1000 은 위에서 9·10점에도 승격 — 다른 선이다. 아래서 들어와 12·13점으로 승격한 사례(1100 ×3)는 설명 못 함.
- 공식 표는 못 찾았다: 넥슨 공지 5212(2025-02)·5456(2025-06)은 1vs1 위주이고 감독모드 승점표가 없다. 나무위키 공식경기 문서는 "경기당 승점을 종합해 결정" 정도(본문은 403 으로 못 열었다). 검색 도구가 미국 기반이라 인벤·디시 글은 못 봤다.
- **다시 볼 조건**: 사용자가 감독모드 승점표를 찾아 주거나(그 표를 정본으로 놓고 위 실측으로 검증) 넥슨이 공개할 때. 추정으로 "이번 회차 승급 불가" 같은 단정 문장을 내지 않는다.

### 포지션 특성 501~1,000위 (2026-10-07 32단계에서 뺐다 — 사용자 U7)

하루 오픈API 300(키의 30%)을 랭커 픽·추천과 나누면 특성 몫이 약 106 이라 500명까지만 14일 정리 안에 돈다. 사용자마다 같은 랭커를 따로 받는 구조라
범위를 넓히려면 "중앙 조회 서버"(아래)가 먼저다 — 서버가 한 번 받아 나눠 주면 사용자 키와 넥슨 웹 요청이 사용자 수에 비례하지 않는다.

### 랭커 팀 전술·개인 전술 (2026-10-07 32단계에서 뺐다 — 사용자 U3)
넥슨 웹 스쿼드메이커(`getingameinfo`)에 팀 전술 10칸·선수별 개인 전술·참여도가 있지만 "지금 켜진 칸" 표시가 없다. 마지막 경기 선발과 같은 칸이
딱 하나인 사람이 25명 중 13(52%) — 40% 는 같은 11명·자리로 내용이 다른 칸이 여럿이라 어느 전술을 썼는지 모른다(9위는 10칸 전부). 개인 전술은
그 칸들끼리 44% 만 같다. 32단계 실측 장부 R1~R3 · 코드표 위치 R8. **다시 볼 조건**: 넥슨이 켜진 칸을 알려 주는 값을 내놓거나, 한 칸만 판정된
절반으로도 보고 싶다는 요청이 올 때(그때 판정 규칙은 32단계 초안 1판 — 커밋 `62f5823`).

### 중앙 조회 서버 (2026-10-07 사용자: "서버를 무료로 운영 가능한 곳을 찾기 전까진 놔둔다")
지금은 사용자마다 자기 넥슨 키를 넣는다. 서비스 단계 등록엔 서비스 URL·이미지가 필요한데, 남들이 이 저장소 주소로 각자 등록해도 되는지는
**확인하지 않았다** — 막히면 다들 개발 단계(하루 1,000)로 떨어진다. 웹 서비스처럼 서버가 서비스 키 하나로 대신 조회·캐시하면 이 문제가 사라지지만,
운영비·장애 시 전원 멈춤·남의 전적이 서버에 쌓임(개인정보·약관 새로)이 따른다. **도입 조건**: 무료로 상시 운영할 곳을 찾았을 때.
그 전에 할 수 있는 것: 넥슨에 "같은 서비스 URL 로 각자 등록" 가능 여부 문의 · 개발 단계 키로도 첫 조회를 며칠에 나눠 매끄럽게(화면 안내).

### 랭커 묶음도 팀컬러를 (이름, 엠블럼)으로 (2.2.1 검토 때 나온 것)
