## 버전 규칙

`a.b.c` — **a** 큰 패치(구조가 바뀌어 새로 익혀야 함: 메뉴 재편 · 저장 형식 큰 변경) · **b** 중간(새 기능·화면) ·
**c** 작은 수정(버그·문구·작은 성능). 섞이면 큰 쪽을 올리고 **아래 자리는 1로** 돌린다(1.4.2 → 2.1.1).
예외: 공개판 1.0.2 의 가운데가 0 이라 창 크기 수정만 1.0.3, 다음 기능 패치(1.1.1)부터 새 규칙.
`updatecheck` 는 세 자리 숫자 비교라 이 체계에서 그대로 동작한다.

## 배포 보호 준비 (2026-10-05 사용자와 결정 — 19단계 끝 · 37~39단계는 나중)

**목표**: 기능이 거의 완성되면 핵심 알고리즘을 쉽게 베끼지 못하게 배포한다. **지금은 개발 편의 우선** — Nuitka·난독화·보호 빌드는 적용하지 않는다.

**정한 것**
- **저장소는 공개 유지(MIT).** 비공개 전환은 기각 — 기존 설치자의 자동 업데이트(`config.LATEST_RELEASE_API`)·릴리스 링크·`.iss` URL·UA 의 주소가
  전부 끊기고, 이미 공개된 커밋의 MIT 허락은 회수되지 않는다.
- **핵심만 가린다** — 그때 가치 있는 알고리즘(예측 등)만 비공개 저장소로, 공개 저장소엔 약속(`core_api`)과 간이 대체만. 배포판엔 **Nuitka 로
  컴파일한 `.pyd`**. 이미 공개된 `analysis.py`·`stats.py` 는 못 가린다 — 가려지는 건 분리 뒤 새로 만들거나 크게 바꾼 것부터.
- **PySide6 전환이 선행 조건** — PyQt6 는 GPL v3 라 숨긴 모듈을 묶은 exe 를 배포하면 위반이다(LGPL 인 PySide6 는 Qt DLL 을 바꿔 끼울 수 있게만 두면 된다).
- **암호화(PyArmor 류)는 안 쓴다** — 실행 때 어차피 풀리고, 모르는 사람에게 주는 exe 라 백신 오탐이 치명적. 컴파일만으로 원문 복원 도구가 안 통한다.
  결과를 보고 공식을 추정하는 것·기계어 분석은 어떤 방법으로도 못 막는다(완전히 막으려면 서버 — 지금 규모엔 과함).
  **기대치**: "파일을 AI 에 던져 원문 받기"는 막지만, Nuitka 는 속성 이름·문자열·상수가 바이너리에 남고 흐름이 C API 호출 나열이라
  디스어셈블러 + AI 로 시간을 들이면 이 규모의 통계 공식은 대부분 되살아난다고 본다. 정말 지킬 알고리즘이 생기면 그것만 서버로 — 그때 다시 판단.

### B3 팀컬러 가성비 — [메타 분석 › 가성비]

- `rankmeta.value_score(conn, top)` → 팀컬러마다 네 값(마지막 스냅숏 · 구간 안): 평균 ELO · 시즌 승÷(승+패)(사람 합) · 구단가치 **중앙값**(R9 — 평균은 1조대 몇 명에 끌려간다) · 챔스 이상 비율(등급 ≤ 1).
- **점수 = 1,000점: 점수 300 · 승률 200 · 구단가치 300(낮을수록) · 챔스 200**(후보 표의 30·20·30·20 을 1,000점으로 — 상수 `config.B3_WEIGHTS`).
  값마다 **인원 `config.B3_MIN_USERS`(20) 이상인 팀컬러 사이 백분위**(같은 값은 평균 순위)로 바꿔 무게를 곱한다. 백분위로 하는 이유: 시즌 승률은 팀컬러 사이 폭이 4%p(R8)라 값 그대로 비례로 하면 흔들림이 점수를 가른다. 20명 미만은 점수 없이 흐림(R7: 1만 39종 · 상위 2,000 23종 · **상위 200 은 2종이라 "표본이 적어 점수를 안 냅니다"**).
  상위 200 의 챔스 비율은 거의 다 100%(R8) — 다 같으면 그 값은 모두 같은 백분위(가르지 않는다).
- 표: 팀컬러 | 점수 | 네 값(각 값의 백분위를 툴팁) | 인원. 안내 줄에 무게와 "백분위 — 다른 구간과 점수를 맞대지 마세요".

### B4 구단가치 분포 — [메타 분석 › 구단가치]

- `rankmeta.value_bins(conn)` → 마지막 스냅숏 1만 명을 **8구간**(경계 = 그 스냅숏 8분위를 두 자리로 반올림 — R9: 27억·43억·…·300억. 저장 안 하니 스냅숏마다 다시) — 구간마다 인원·점유율 · 평균 ELO · 시즌 승÷(승+패) · 챔스 비율.
- **구간 × 팀컬러 표**(2026-10-07 보강): 줄 = 팀컬러(1만 20명 이상), 칸 = 8구간의 점유(그 팀컬러 인원 중 그 구간 %)와 챔스 비율. 챔스 비율 색은 **구간 평균 대비**, 값은 **윌슨 하한**(인원이 적으면 크게 깎인다)으로 칠한다. 칸 인원 5 미만은 빈칸.
- **구간 가성비 상위**: 구간마다 평균 ELO 상위 팀컬러 3개(그 구간 인원 5 이상).

### B6 구간 평균 — [메타 분석 › 구간 평균]

- `rankmeta.tier_means(conn, top)` → 팀컬러·포메이션마다 인원 · 평균 ELO · 구단가치 중앙값(툴팁에 평균). 구간 콤보 `META_TOP_TIERS` · 포메이션 묶기(N6).

### N6 포메이션 묶기

- 포메이션 표가 있는 탭(B1 메타 변화 · B2 · B6)에 콤보 "그대로 · 수비 줄 수 · 앞줄 수". 묶기는 `rankmeta.formation_group(text, how)`(한 곳).
  - 수비 줄 수 = 첫 숫자(3·4·5백) · 앞줄 수 = **끝 숫자**(R10 — 데이터센터 표기의 마지막 줄. "스트라이커"가 아니라 "앞줄 N명"으로 적는다: 윙어가 섞인다).
  - 빈 값·숫자가 아닌 것·첫 숫자가 3~5 밖(R10 `1-1-4-1-3`)은 "기타·모름".
- B1 은 화면이 `rankmeta.group_meta(trend, how)` 로 묶는다(1회차 [중]): `MetaTrend.rows["formation"]` 의 `now_n`·`then_n` 을 묶음 키로 더하고 비율·차·`thin`(묶은 인원으로 `META_MIN_USERS`)을 **다시 계산**한다. `rankcollect.meta_trend` 는 안 고친다(rankmeta 가 rankcollect 를 가져다 쓰는 쪽 — 거꾸로 부르지 않는다).
- ⚠ R10: 수비 줄 수는 지금 4백이 99.8% 라 거의 한 줄이다 — 그래도 둔다(시즌 메타가 바뀌면 의미가 생긴다). 기본은 "그대로".

### N10 승률 → 하루 점수 — [메타 분석 › 승률→점수]

- `rankmeta.winrate_to_elo(conn, top=10000)`(구간은 **앞 스냅숏 순위** — 진입점 표와 같게) → 지금 시즌 원본 14일의 **하루 걸음 쌍 전부**(`PREDICT_STEP_GAP_H`)에서 사람마다 (하루 승÷(승+패), ELO 차, 판 수). 판 `config.N10_MIN_GAMES`(초안 10) 미만은 뺀다(승률이 0·50·100% 로 튄다).
- 칸 `config.N10_BINS`(5%p — 35~65% 밖은 한 칸씩 묶음) → 칸마다 걸음 수 · 평균 · 중앙값 · 오른 날 비율 · 5~95% 폭. **손익분기** = 중앙값이 0 을 지나는 곳(이웃 두 칸 사이 직선 보간 — R12).
- 검색 계정 한 줄: "최근 하루 승률이 비슷한(±2.5%p) **같은 점수대(±100)** 사람들은 하루 중앙값 +N점(걸음 M개)". 내 하루 승률 = 내 경기 중 마지막 24시간의 감독모드(무승부 뺌 · 10판 미만이면 줄 없음). **내 ELO** = 마지막 스냅숏의 내 줄(`find_sn`) → 없으면 `self._elo[ouid]` 의 마지막 값(EloLoader) → 둘 다 없으면 점수대 없이. 그래서 `wrelo` 는 `rank_ready`·EloLoader 끝(`elo_saved` 포함)에도 무효화한다. 점수대 걸음이 `config.PREDICT_MIN_STEPS`(300) 미만이면 ±200 → 그래도 모자라면 점수대 없이(제목에 적음).
- 안내 줄: "1만 위 밖으로 떨어진 날은 빠져 낮은 승률 칸이 실제보다 덜 떨어집니다"(R1).
- 쌍이 `PREDICT_MIN_PAIRS`(3) 미만이면 "모으는 중"(예측과 같은 조건).

### N13 주간 요약 — [랭킹 추이 › 주간 요약]

- `rankmeta.weekly(conn, my_sn, season_end, top)` — 기준 = 마지막 스냅숏. 비교 스냅숏은 **항목마다 따로**(1회차 [중]): 컷 변화는 영구 `cut_elo` 라 `_season_snaps` 전체에서 · 급상승은 **원본이 남은 스냅숏만** 후보로 — 둘 다 데이터 시각 7일 전 ±1일(`_nearest`), 없으면 3일 이상 전 가장 옛것 · 실제 일수를 제목에.
  - **컷 변화**: 200·1,000·1만 위 ELO(영구 `cut_elo`) 그때 → 지금.
  - **급상승 10명**: **ELO 가 가장 많이 오른 사람**(**두 시점 다 1만 위 안이던 사람만** — 안내 줄에) · 닉네임(지금 것)·그때 → 지금 순위·ELO 차(U3). 순위 차로 고르지 않는 이유(1회차 [중]): 아래쪽은 점수 몇십에 순위 수백이 움직여 상위 10명이 거의 다 8천~1만 위가 된다.
  - **하루 최다 승 10명**(U4): 이웃 쌍 사이 승 수 · 승·무·패.
  - **팀컬러별 최고·최저 구단가치**: 팀컬러(인원 5 이상)마다 가장 비싼·싼 구단주 닉네임·순위·구단가치(U3) — 구간 콤보.
  - **구단가치 등수**: 검색 계정이 마지막 스냅숏에 있으면 "구단가치 N등 / 1만(상위 x%)".
  - **주차 중**(200위 안 · 시즌 종료 7일 이내 · 이웃 쌍 사이 0판): 종료일은 예측과 같은 길 — `predict_for` 안의 "공지 → 끝난 시즌 길이로 추정"(predict.py:494-504)을 함수 `predict.season_end_estimate(seasons, notice, today)` 로 꺼내 둘이 같이 쓴다(1회차 [중] — `resolve_notice` 는 공지 대조만 한다). 예측 골든(`test_predict.GOLDEN_VALUE`)이 그대로여야 한다. 화면이 계산해 `weekly` 에 넘긴다. 종료 7일 밖이면 칸을 숨기고 "시즌 끝 7일 전부터 보입니다". 종료일을 모르면 "종료일을 몰라 안 냅니다".
- 원본이 7일치 안 되면 급상승만 "모으는 중" · 컷 변화는 영구 집계라 그대로 · 나머지(이웃 쌍·마지막 스냅숏만 쓰는 것)는 보인다.

### N8 순위 변동 원인 · N9 변동 이력 — [승률 그래프 › 순위 변동] (검색 계정)

- 대상 프로필 번호: `self._rank.profile_sn` → 없으면 마지막 스냅숏에서 닉네임으로(R14 — `sync_tracked_elo` 와 같은 순서, 함수 하나 `rankmeta.find_sn(conn, sn, nickname)`) → 그래도 없으면 "최근 14일 안 1만 위 안에 없거나 랭킹 수집이 꺼져 있습니다".
- `rankmeta.rank_moves(conn, sn)` → **쌍은 지금 시즌의 원본이 남은 스냅숏 전부**로 만들고(데이터 시각 순 · 간격 > 36시간이면 "수집 빠짐") 그 사람 줄(`idx_rows_sn`)을 거기에 붙인다(1회차 [상] — 그 사람 줄로 쌍을 만들면 가운데 스냅숏에서 1만 위 밖이던 날이 48시간 쌍이 되어 "수집 빠짐"으로 나왔다). 판정은 **위에서부터 처음 맞는 것**(1회차 [중] — 0판에 순위·ELO 둘 다 바뀌면 둘에 걸렸다):
  | 판정 | 조건(쌍 사이) |
  |---|---|
  | 경기 | 판 수 > 0 · 팀컬러·포메이션 그대로 |
  | 경기 + 스쿼드 | 판 수 > 0 · 팀컬러나 포메이션 바뀜 |
  | 스쿼드만 | 판 수 0 · 팀컬러나 포메이션 바뀜 |
  | 밀림 | 판 수 0 · 팀컬러·포메이션·ELO 그대로 · 순위만 바뀜(R4 — 하루 604명) |
  | 점수만 바뀜 | 판 수 0 · 팀컬러·포메이션 그대로 · ELO 바뀜(R4 — 하루 3명, 이유 모름) |
  | 그대로 | 판 수 0 · 순위·ELO 그대로 |
  | 1만 위 밖 | 한쪽에 없음 (맨 먼저 본다) |
  실제 순서: 1만 위 밖 → 경기 + 스쿼드 → 경기 → 스쿼드만 → 점수만 바뀜 → 밀림 → 그대로(표의 줄 순서와 다르면 이 줄이 정본). **구단가치는 판정에 안 쓴다**(R3 — 매일 모두 바뀐다). **등급도 안 쓴다**(후보 표는 "스쿼드만"에 등급을 넣었다 — 등급은 경기 결과나 자정 정산으로만 바뀌어 스쿼드를 바꿨다는 신호가 아니다. 등급 변화는 칸으로만 보인다). 칸: 날짜 · 순위(차) · ELO(차) · 승·무·패 · 판정.
- **N9 이력** 같은 탭 아래 표: 스냅숏마다 포메이션 · 팀컬러 · **"닉네임 바뀜" 표시**(U2 — 옛 이름 안 보임). 바뀐 칸만 굵게.
  내 경기 쪽은 **같은 칸에 섞지 않는다**(R11 — 표기가 다르다): 쌍 사이 내 감독모드 경기 수(DB)를 "기록된 경기" 칸으로 — 넥슨 판 수와 다르면(검색 안 한 사이 경기 · 다른 모드) 그대로 둘 다 보인다.
- 다른 계정으로 검색하면 다시 그린다(검색 결과에 묶인 화면 — `_invalidate`). **프로필 번호가 늦게 오면**(`rank_ready` → `_on_rank_ready`, app_main.py:5788 — 지금은 랭커 카드만) `rankmove`·`wrelo`·`weekly` 도 무효화한다(1회차 [중]).

### N7 상대가 쓰는 카드 — [포지션별 최다 상대 › 카드별]

- `stats.opponent_cards(details, ouid, nicknames=None)`(새 · `opponent_position_players` 옆) → 자리마다 카드(spId) 목록: 만난 판 · **사용률 = 그 자리에 그 카드가 선발로 나온 판 ÷ 그 자리가 나온 판** · 그 카드를 만난 판의 내 승·무·패와 승률(승÷전체 — R15). 교체 명단 뺌(지금 함수와 같은 규칙).
- 화면: 자리 콤보(공격→미들→수비→GK 순 — `_position_group_rank`) + 표(카드 | 사용률 | 만난 판 | 내 승·무·패 | 승률). 만난 판 `config.OPP_CARD_MIN`(초안 5) 미만 흐림. 이름·얼굴은 지금 표처럼 `self._names`.
- **"1만 위 안 상대만"** 체크: 원본이 남은 지금 시즌 스냅숏 닉네임 전부(`rankmeta.ranked_nicknames(conn)` — 14일 안 한 번이라도 1만 위 안) 와 상대 닉네임 대조. 체크하면 안내 줄에 "최근 14일 안 1만 위 안에 든 닉네임 · 닉네임을 바꾼 상대는 빠질 수 있음". rank.db 가 없으면 체크를 끈다(툴팁 이유).
- 범위: 지금 화면과 같은 시즌 콤보(`_teamcolor_scope`).
- **팀컬러 필터**(1회차 [상] — 콤보 `cb_position_color` 는 `_build_position_opp_tab` 안이라 탭으로 나누면 [축구장] 에만 있고, `_on_position_color_changed`(app_main.py:5393)는 축구장만 직접 그린다): [카드별] 탭에 **자기 콤보 + 찾기 칸**을 둔다 — 목록은 `_refresh_position_color_options` 가 두 콤보를 같이 채우고(고른 값은 탭마다 따로 · 없어지면 그 탭만 "전체"), 바꾸면 `_invalidate("oppcards")`. 팀컬러를 새로 읽은 길(`_invalidate("teamcolor")`, app_main.py:2914 자리)에서 `oppcards` 도 같이 무효화한다.

1. 마지막 감독모드 경기 선발의 (카드, 자리) 11쌍과 **11/11 로 맞는 칸이 정확히 하나**면 그 칸. 둘 이상이거나 없으면 **판정 못 함**(짐작 안 함 · 집계에서 뺀다).
2. 경기의 자리(`spPosition` 설명)와 칸의 `role` 은 같은 표기(소문자)로 맞댄다 — 10-06 실측 30위 구단주: 60칸 중 대표 C · 전술 3 하나만 11/11.
3. 카드는 팀(A/B/C)끼리 같은 경우가 많아(30위: 대표 A·B·C 전부 11/11) 거르기에 약하다 — 각 팀 전술 1 로 카드를 보고 클럽 등 안 맞는 팀만 뺀 뒤 나머지 전술을 다 받는다(처음 판정 한 명 약 36요청 · 약 650KB).
4. 판정 뒤에는 **찾은 칸 하나만** 다시 확인(1요청). 안 맞으면 그때 다시 전부.
5. 판정률은 계획 검토 때 20명 이상으로 잰다(옛 경로 실측은 85% — 새 경로는 자리까지 맞아 더 높을 것으로 본다, 아직 1명).

**대상과 마지막 경기의 출처**
| 구간 | 마지막 경기 | 쓰임 |
|---|---|---|
| 1~200 | 랭커 픽이 이미 받는 경기 | 인기 전술 |
| 201~2,000 | 오픈API — **하루 400 상한**(랭커 픽 300 과 합쳐 700 — 사용자 검색 몫을 남긴다) · 약 10일에 한 바퀴 | 인기 전술 |
| 2,001~10,000 | **내 DB 의 상대 경기만**(요청 0 · 10-06 실측 30일 1만 위 안 상대 2,179명) | **"이 상대가 쓰는 전술"**(상대 전적·구단주 비교) — 인기 전술 통계에는 **섞지 않는다**(내 점수대로 치우친 표본) |
- 스냅숏 승·무·패가 그대로인 사람은 새 경기가 없으니 다시 확인하지 않는다.
- **첫 바퀴는 나눠 돈다** — 2,000명 첫 판정이 웹 약 7.2만 요청(약 1.3GB)이라 하루 상한(예: 300~500명)을 두고 위 순위부터. 화면에 "전술이 수집된 구단주 N명"과 진행을 띄운다.
- 인기 전술은 칸별 최빈값을 모으지 않는다(아무도 안 쓰는 조합이 나온다) — **한 사람의 전술을 통째로** 묶어 "N명이 같은 값". 포메이션별 · 구간(200 / 2,000) 필터.

**보완 (2026-10-07 조사)**
- 11/11 로 맞는 칸이 여럿이어도 **전술 내용까지 같으면 한 칸으로 합친다**(판정 못 함을 줄인다). 내용이 다르면 지금처럼 판정 못 함.
- 칸마다 포메이션이 따로 저장된다(경기는 4-1-4-1-0 인데 칸은 5-1-2-1-1 인 예를 봤다) — 판정 때 칸의 포메이션과 경기 포메이션도 같이 맞댄다.
- 같은 응답에 카드마다 **유저가 넣은 일반·신규·훈련 특성과 코치**, 발동 팀컬러가 온다 → **부여 특성 사용률**을 여기서 같이 만든다(요청 추가 0):
  자리별 일반(5강~)·신규(8강~)·훈련(11강~)·코치(카드당 최대 3 — 합이 100% 를 넘는다). 분모는 화면마다 — 자리 표는 칸이 안 열린 선수까지, 카드 상세는 칸을 채운 사람만.
  자리마다 한 줄만 낼 때는 **그 자리 비율 ÷ 전체 비율**로 고른다(어디서나 1위인 특성이 모든 자리를 덮지 않게) + 5% 문턱 · 한 자리 전용 특성(GK)은 많이 넣은 순.
  "하지 않기로 한 것"에서 옮겼다(그때 이유가 "공개 데이터에 없음"이었는데 이 출처에 있다).
- 검색한 계정·비교 상대는 누를 때 바로(웹 약 36 + 오픈API 2).

**지켜야 할 것** — 남의 스쿼드·전술을 저장하므로 이용 안내를 고치고 `NOTICE_VERSION` 을 올린다 · 랭킹 수집 토글과 같이 꺼지고 지우기 경로(`purge_*`)를 둔다 ·
차단 3회면 스스로 끔(수집기 D6 그대로) · 응답 구조가 바뀌면 멈추고 알린다(내부 호출이라 예고 없이 바뀔 수 있다).

**나중에 (조건부)** — 1만 명을 매일 채우고 싶어지면: 오픈API **서비스 단계 키**(하루 2,000만 · 개발 단계는 1,000)로 수집 쪽만 따로 돌리고(예: 하루 한 번 모아 결과 파일만 배포) 앱은 그걸 받는다.
**서비스 키는 exe 에 넣지 않는다**(꺼내 쓰이면 키가 막혀 모두 멈춘다). 판정·저장·화면은 이 절 그대로, 마지막 경기 출처만 바뀐다. 웹 요청량(1만 명 첫 바퀴 약 36만 요청 · 약 6.5GB)은 키와 무관하게 남는다.

## 버전 미정 후보

### 중앙 조회 서버 (2026-10-07 사용자: "서버를 무료로 운영 가능한 곳을 찾기 전까진 놔둔다")
지금은 사용자마다 자기 넥슨 키를 넣는다. 서비스 단계 등록엔 서비스 URL·이미지가 필요한데, 남들이 이 저장소 주소로 각자 등록해도 되는지는
**확인하지 않았다** — 막히면 다들 개발 단계(하루 1,000)로 떨어진다. 웹 서비스처럼 서버가 서비스 키 하나로 대신 조회·캐시하면 이 문제가 사라지지만,
운영비·장애 시 전원 멈춤·남의 전적이 서버에 쌓임(개인정보·약관 새로)이 따른다. **도입 조건**: 무료로 상시 운영할 곳을 찾았을 때.
그 전에 할 수 있는 것: 넥슨에 "같은 서비스 URL 로 각자 등록" 가능 여부 문의 · 개발 단계 키로도 첫 조회를 며칠에 나눠 매끄럽게(화면 안내).

### 랭커 묶음도 팀컬러를 (이름, 엠블럼)으로 (2.2.1 검토 때 나온 것)
